## 1. 개요 (Overview)

기본정보기술자시험(基本情報技術者試験, FE) **과목 A(科目A)**의 약 65~70%(60문항 중 약 40문항)를
차지하는 **테크놀로지계(テクノロジ系)** 핵심 이론과 빈출 계산 공식을 정리하고, 기출 학습 내용을 누적
기록하는 노트입니다.

## 2. 기초이론 (基礎理論)

### 2.1 기수 변환 및 음수 표현 (2의 보수)

- **기수 변환 (基数変換)**:
  - 2진수 4비트는 16진수 1자리와 1:1 대응됩니다 ($0000_2 = 0_{16}$, $1111_2 = \text{F}_{16}$).
  - 소수점 이하 10진수를 2진수로 변환할 때는 소수부에 계속 $2$를 곱하며 정수 자리를 순서대로
    취합니다.
- **2의 보수 (2の補数)**:
  - 컴퓨터에서 음수를 표현하는 표준 방식으로, **모든 비트를 반전(1의 보수)시킨 뒤 $1$을 더하여**
    구합니다.
  - $n$비트 2의 보수 표현 범위: $-2^{n-1} \sim 2^{n-1} - 1$ (예: 8비트 기준 $-128 \sim +127$).
- **시프트 연산 (シフト演算)**:
  - **논리 시프트 (論理シフト)**: 부호 비트를 고려하지 않고 빈자리를 무조건 `0`으로 채웁니다.
  - **산술 시프트 (算術シフト)**: 부호 비트(MSB)를 유지하면서 이동합니다. 왼쪽으로 $n$비트
    시프트하면 $\times 2^n$, 오른쪽으로 $n$비트 시프트하면 $\div 2^n$ (빈자리는 부호 비트로 채움)이
    됩니다.

### 2.2 대기행렬 이론 ($M/M/1$ 모델)

창구나 서버에 요청이 도착하여 처리될 때까지의 평균 대기 시간을 계산하는 빈출 공식입니다.

- **이용률 ($\rho$, 窓口利用率)**:
  $$\rho = \frac{\text{평균 도착률 }(\lambda)}{\text{평균 서비스율 }(\mu)} = \frac{\text{평균 서비스 시간}}{\text{평균 도착 간격}}$$
- **평균 대기 시간 ($W_q$, 平均待ち時間)**:
  $$W_q = \frac{\rho}{1 - \rho} \times \text{평균 서비스 시간}$$
- **평균 응답 시간 ($W$, 平均応答時間 = 대기 시간 + 서비스 시간)**:
  $$W = W_q + \text{평균 서비스 시간} = \frac{1}{1 - \rho} \times \text{평균 서비스 시간}$$

## 3. 컴퓨터 시스템 (コンピュータシステム)

### 3.1 캐시 메모리 실효 액세스 시간 (実効アクセス時間)

CPU가 원하는 데이터가 캐시 메모리에 존재할 확률을 **히트율(ヒット率, $h$)**이라고 할 때, 평균 메모리
접근 시간은 다음과 같습니다.

$$\text{실효 액세스 시간} = (\text{캐시 접근 시간} \times h) + \{\text{주기억장치 접근 시간} \times (1 - h)\}$$

- **라이트 스루 (ライトスルー, Write-Through)**: 캐시와 주기억장치에 동시에 데이터를 기록하는 방식
  (일관성 유지가 쉬우나 쓰기 속도가 느림).
- **라이트 백 (ライトバック, Write-Back)**: 캐시에만 먼저 기록하고, 캐시 블록이 교체될 때
  주기억장치에 반영하는 방식 (쓰기 속도가 빠르나 제어 회로가 복잡함).

### 3.2 시스템 신뢰성 및 가동률 (稼働率) 계산 ⭐

시스템의 신뢰도를 평가하는 **RASIS** 지표(Reliability, Availability, Serviceability, Integrity,
Security) 중 가동률($A$) 계산은 매 시험마다 출제됩니다.

- **$MTBF$ (Mean Time Between Failures, 평균 고장 간격)**: 시스템이 정상 가동된 평균 시간.
- **$MTTR$ (Mean Time To Repair, 평균 수리 시간)**: 고장 발생 후 복구까지 걸린 평균 시간.
- **단일 시스템 가동률 ($A$, 稼働率)**: $$A = \frac{MTBF}{MTBF + MTTR}$$
- **직렬 연결 시스템 (直列システム)**: 모든 장치가 정상이어야 전체 시스템이 작동함.
  $$A_{\text{직렬}} = A_1 \times A_2$$
- **병렬 연결 시스템 (並列システム / デュプレックス)**: 하나만 정상이어도 전체 시스템이 작동함
  ($1 - \text{모두 고장 날 확률}$). $$A_{\text{병렬}} = 1 - (1 - A_1)(1 - A_2)$$

## 4. 기술요소: 데이터베이스 및 네트워크 (技術要素)

### 4.1 데이터베이스 정규화 및 트랜잭션

- **정규화 (正規化)**: 데이터 중복을 제거하고 이상 현상(갱신/삽입/삭제 이상)을 방지하는 과정입니다.
  - **제1정규형 (1NF)**: 반복되는 그룹이나 다중값 속성을 제거하여 모든 도메인을 원자값으로 만듦.
  - **제2정규형 (2NF)**: 기본키가 복합키일 때, 기본키의 일부에만 종속되는 **부분 함수
    종속(部分関数従属)**을 제거.
  - **제3정규형 (3NF)**: 기본키가 아닌 일반 속성 간의 종속인 **이행적 함수 종속(推移的関数従属,
    $A \rightarrow B \rightarrow C$)**을 제거.
- **ACID 특성**:
  - **Atomicity (원자성)**: 모두 반영되거나 전혀 반영되지 않음 (All or Nothing).
  - **Consistency (일관성)**: 트랜잭션 전후 데이터 무결성 제약조건 유지.
  - **Isolation (고립성/격리성)**: 실행 중인 트랜잭션의 중간 결과를 다른 트랜잭션이 볼 수 없음.
  - **Durability (지속성/영속성)**: 커밋된 결과는 시스템 장애가 발생해도 영구 보존됨.
- **장애 복구 (障害回復)**:
  - **롤백 (ロールバック, Rollback / Undo)**: 장애 발생 시점까지 커밋되지 않은 트랜잭션을 갱신 전
    로그(Before-Image)를 이용해 취소.
  - **롤포워드 (ロールフォワード, Rollforward / Redo)**: 백업 시점 이후 커밋 완료된 트랜잭션을 갱신
    후 로그(After-Image)를 이용해 재적용.

### 4.2 네트워크 및 정보보안 기초

- **OSI 기본 참조 모델과 네트워크 장비**:
  - L1 물리 계층: 리피터(リピータ), 허브
  - L2 데이터링크 계층: 브리지(ブリッジ), L2 스위치 (MAC 주소 기반 전달)
  - L3 네트워크 계층: 라우터(ルータ), L3 스위치 (IP 주소 기반 경로 선택)
  - L4~L7: 게이트웨이(ゲートウェイ), L7 스위치 / 로드밸런서
- **공개키 암호 방식 vs 전자서명 키 사용 구분**:

| 목적                          | 암호화(생성)에 사용하는 키  | 복호화(검증)에 사용하는 키  | 핵심 효과              |
| :---------------------------- | :-------------------------- | :-------------------------- | :--------------------- |
| **기밀성 보장 (공개키 암호)** | **수신자의 공개키**         | **수신자의 개인키(비밀키)** | 도청 방지 (기밀성)     |
| **무결성 및 인증 (전자서명)** | **발신자의 개인키(비밀키)** | **발신자의 공개키**         | 위변조 탐지, 부인 방지 |

## 5. 개발기술 (開発技術)

### 5.1 소프트웨어 테스트 단계 (V자 모델)

1. **단위 테스트 (単体テスト, Unit Test)**: 모듈 단위의 기능 및 내부 로직 검증. 화이트박스
   테스트(명령문/분기/조건 커버리지)와 블랙박스 테스트 병행.
2. **결합 테스트 (結合テスト, Integration Test)**: 모듈 간 인터페이스 연동 검증. 상향식(드라이버
   ドライバ 사용) vs 하향식(스텁 スタブ 사용).
3. **시스템 테스트 (システムテスト, System Test)**: 기능 요구사항뿐만 아니라 성능, 부하, 보안 등
   비기능 요구사항을 종합 검증.
4. **인수 테스트 (受入テスト, Acceptance Test)**: 발주자(사용자)가 실제 업무 환경에서 요구사항 충족
   여부를 최종 확인.
