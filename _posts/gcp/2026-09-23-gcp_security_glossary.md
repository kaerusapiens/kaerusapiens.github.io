## 1. 개요 (Overview)

Google Cloud Platform(GCP) 및 엔터프라이즈 클라우드 보안 환경에서 자주 등장하는 핵심 보안 전문
용어들을 정리하고 지속적으로 누적하는 사전형 아카이브입니다.

---

## 2. 보안 핵심 용어 사전 (Glossary)

### A

#### Accountability (결과 책임 / 최종 설명 책임) ⭐

- **정의**: 업무나 프로젝트가 완료된 후, 그 결과(성패, 규정 준수 여부)에 대해 평가받고 정당성을
  입증·설명해야 하는 **최종적·사후적인 책임**입니다.
- **핵심 속성 (RACI 매트릭스의 'A')**:
  - **위임 불가 (Non-delegable)**: 실행 작업은 다른 사람에게 위임할 수 있어도, 최종 결과에 대한
    책임은 결코 타인에게 넘길 수 없습니다.
  - **단일 소유자 (Single Ownership)**: 책임의 소재를 명확히 하기 위해 단 한 사람(또는 단일
    주체)에게만 귀속되는 것이 원칙입니다.
- **클라우드 보안 및 거버넌스 맥락**:
  - **공유 책임 모델(Shared Responsibility Model)**: 클라우드 인프라의 물리 보안은 CSP(Google)가
    담당하지만, 데이터 거버넌스 및 고객사 환경 침해 사고에 대한 법적·규제적 **최종 결과
    책임(Accountability)은 항상 고객사(데이터 소유자)**에게 있습니다.
  - CISO나 보안 책임자는 보안 구현 과업(Responsibility)을 실무 엔지니어에게 위임할 수 있으나, 규제
    기관(GDPR, ISMS-P 등)에 대한 최종 소명 책임(Accountability)은 본인이 집니다.

#### Autonomy (자율성 / 자주권 / 자치권) ⭐

- **정의**: 외부의 간섭이나 중앙의 직접적인 통제 없이, 조직, 개별 팀, 시스템, 또는 소프트웨어
  에이전트가 **스스로 판단하고 독립적으로 의사결정을 내리며 운영될 수 있는 권한이나 성질**을
  의미합니다.
- **클라우드 및 보안 아키텍처 맥락**:
  - **팀 자율성과 거버넌스의 조화 (Team Autonomy vs. Central Governance)**:
    - 중앙 보안팀이 모든 리소스 생성을 일일이 승인하면 배포 병목이 발생합니다.
    - 엔터프라이즈 환경에서는 최상위 조직 정책(Organization Policy)과 가드레일만 중앙에서 강제하고,
      개별 개발팀(프로젝트/폴더)에는 **인프라 프로비저닝과 IAM 관리에 대한 자율성(Autonomy)**을
      위임하는 멀티 테넌트 거버넌스 모델을 구축합니다.
  - **자율 운영 및 자가 치유 (Autonomous Operations & Self-Healing)**:
    - 보안 위협이나 장애 발생 시 엔지니어의 수동 개입 없이, 시스템이 사전 정의된 규칙이나 정책에
      따라 침해 인스턴스 격리, 키 교체, 트래픽 차단 등을 자동으로 수행하는 자율 방어 체계입니다.
  - **디지털 주권 및 데이터 자치권 (Digital / Data Sovereignty)**:
    - 클라우드 서비스 제공자(CSP)나 외부 기관의 통제에 종속되지 않고, 기업이 자체 데이터 및 암호화
      키에 대한 **완전한 통제권과 독립된 자주권(Autonomy)**을 보장받기 위해 Cloud EKM(External Key
      Manager) 등을 적용하는 전략입니다.

### C

#### CDE (Cardholder Data Environment, 카드 소유자 데이터 환경)

- **정의**: 신용카드 번호(PAN), 유효기간, CVV 등 결제 카드 데이터가 단 1바이트라도 저장, 처리,
  전송되는 모든 시스템(서버, 네트워크, DB)의 물리적/논리적 영역.
- **보안 포인트**: PCI DSS 규정 준수를 위해 일반 사내망 및 일반 웹 환경과 프로젝트/네트워크 단위로
  완벽히 격리(Isolation)해야 합니다.

#### CEL Predicate (Common Expression Language 서술어 / 조건식) ⭐

- **정의**: Google이 개발한 오픈소스 표현식 언어인 **CEL(Common Expression Language)** 환경에서 특정
  조건을 평가하여 **참(true) 또는 거짓(false)**의 불리언(Boolean) 값을 반환하는 논리
  조건식(함수)입니다.
- **컴퓨터 과학적 배경**: 'Predicate(서술어/조건자)'는 값을 입력받아 불리언을 반환하는 함수를
  의미하며, CEL 내에서는 주로 리스트나 맵 같은 컬렉션 데이터를 다루는 매크로(Macros, 예: `all()`,
  `exists()`)와 함께 사용됩니다.
- **GCP 보안에서의 주요 활용처**:
  - **Security Command Center (SCC) Custom Module**: 리소스의 속성(라벨, 회전 주기 등)이 보안 정책을
    위반했는지(`true`/`false`) 실시간 판정.
  - **Cloud IAM Conditions**: 접속 시간, 사용자 IP, 리소스 태그 조건에 따라 권한 부여 여부를
    동적으로 판정.
  - **Organization Policy Custom Constraints**: 생성/수정 요청된 리소스의 속성을 평가하여 배포
    허용(`ALLOW`) 또는 차단(`DENY`) 판정.

#### CIDR (Classless Inter-Domain Routing, 사이더 표기법) ⭐

- **정의**: IPv4 주소에서 네트워크 영역(동네 이름)과 호스트 영역(컴퓨터 번호)을 구분하기 위해
  슬래시(`/`) 뒤에 고정 비트 수를 명시하는 표기법입니다.
- **핵심 수학 원리**:
  - IPv4는 32비트(32개의 2진수 스위치)로 구성됩니다.
  - `/28`은 앞 28비트를 네트워크 주소로 고정하고, 남은 4비트($32 - 28$)로 호스트 번호를 만듭니다.
  - 4비트로 만들 수 있는 경우의 수는 $2^4 = 16$개(`0000(0)`부터 `1111(15)`까지)입니다.
- **GCP 서브넷 예약 4대 IP**:
  - 클라우드 인프라가 4개(`.0` 네트워크, `.1` 기본 게이트웨이, `.2` 구글 DNS, `.15` 브로드캐스트)를
    자동 예약하므로, 사용자가 실제 쓸 수 있는 가용 IP는 전체 IP에서 4개를 뺀 수량(예: `/28`의 경우
    $16 - 4 = 12$개)입니다.

#### Cloud DNS (클라우드 DNS) ⭐

- **정의**: 사람이 읽기 쉬운 도메인 이름(예: `db.corp.internal`)을 컴퓨터가 통신할 수 있는 사설/공용
  IP 주소로 상호 변환(이름 해석)해 주는 **초고가용성 완전 관리형 글로벌 도메인 네임 서비스**입니다.
- **VPC 및 서브넷과의 차이**:
  - **VPC/서브넷**: 패킷이 직접 이동하는 가상 도로망 및 IP 대역 자체를 정의합니다.
  - **Cloud DNS**: 서버의 사설 IP가 변경(재시작, 오토스케일링)되더라도 클라이언트가 수정 없이 도메인
    이름으로 목적지를 찾을 수 있도록 안내해 주는 **'사옥 내선 전화번호부'** 역할을 수행합니다.
- **핵심 보안 기능 (Private Managed Zone)**:
  - 외부 인터넷에 내부 도메인 및 사설 IP가 노출되지 않도록 **특정 VPC에만 바인딩되는 비공개 프라이빗
    존**을 생성할 수 있습니다.
  - 온프레미스 사내망과 하이브리드 연결 시 DNS 피어링(Peering) 및 포워딩 정책을 통해 단일 도메인
    체계를 안전하게 구현합니다.

#### Cloud IDS (Cloud Intrusion Detection System, 침입 탐지 시스템) ⭐

- **정의**: Palo Alto Networks의 위협 엔진을 탑재하여, 네트워크 트래픽의 **패킷 미러링(Packet
  Mirroring) 복사본을 분석**해 악성코드, 취약점 공격(Exploit), 내부 횡적 이동(Lateral Movement)을
  실시간 감지하는 **대역 외(Out-of-band) 침입 탐지 서비스**입니다.
- **핵심 아키텍처 및 안전성 (Zero Risk of Blocking)**:
  - 원본 패킷이 직접 통과하는 것이 아니라 복제본만 검사하므로, **시그니처 오탐(False Positive)이
    발생해도 운영 트래픽이 차단되거나 간섭받을 위험이 0%**입니다. 무중단 가용성이 필수적인 운영
    환경에 적합합니다.
- **설계 제약**: 모니터링할 서브넷과 **반드시 동일 리전**에 엔드포인트를 프로비저닝하고 패킷 미러링
  정책을 연결해야 합니다.

#### Cloud NGFW (Cloud Next-Generation Firewall, 차세대 방화벽) ⭐

- **정의**: 기존 L3/L4 방화벽을 넘어 L7 애플리케이션 식별, FQDN 기반 아웃바운드 필터링, GeoIP 위치
  제어, 침입 방지(Threat Prevention / IPS)를 제공하는 **인라인(In-line) 완전 관리형 방화벽**입니다.
- **Threat Prevention 동작 원리**:
  - 트래픽이 방화벽 코어를 직접 통과하므로 악성 트래픽 감지 시 **패킷을 즉시 드롭(Drop)하거나 세션을
    강제 종료(Reset)**하여 능동 차단합니다.
  - **주의점**: 시그니처 오탐 발생 시 정상적인 운영 비즈니스 트래픽까지 차단될 위험이 상존합니다.

#### CMEK (Customer-Managed Encryption Keys, 고객 관리 암호화 키)

- **정의**: 클라우드 기본 암호화 대신, 고객사 보안팀이 직접 생성, 회전 주기 설정, 권한 제어, 파기를
  관리하는 암호화 키(Cloud KMS).

#### CryptoKey (크립토키)

- **정의**: Cloud KMS에서 생성하는 명명된 암호화 키 객체(컨테이너)로, 내부에 여러 개의 키
  버전(`CryptoKeyVersion`)을 관리하여 무중단 자동 키 회전(Key Rotation)을 가능하게 합니다.

### D

#### Deterministic (결정론적 / 확정적) ⭐

- **정의**: 동일한 입력값(Input)이 주어지면, 몇 번을 실행하든 **언제나 완전히 동일한
  출력값(Output)을 반환하는 성질**을 뜻합니다. 외부 상태나 무작위 요소(Randomness)의 개입 없이
  결과가 100% 예측 가능(Predictable)합니다.
- **클라우드 보안 및 암호화(GCP) 맥락**:
  - **결정론적 암호화 (Deterministic Encryption)**:
    - 일반 암호화(무작위 솔트/IV 사용)와 달리, 동일한 암호키와 평문("홍길동")에 대해 언제나 동일한
      암호문을 생성합니다.
    - **BigQuery / 데이터 분석 활용**: 데이터를 복호화하지 않고도 암호화된 상태 그대로 등가
      조인(`JOIN`), 필터링(`WHERE email = '...'`), 중복 제거(`DISTINCT`)를 수행할 수 있어 기밀성을
      유지하면서 빅데이터 분석이 가능합니다. (GCP AEAD 결정론적 암호화 함수 지원)
  - **난수 생성과의 대조**:
    - 소프트웨어 난수(**PRNG**)는 시드(Seed) 값이 같으면 다음 난수가 결정론적(Deterministic)으로
      계산되어 해커에게 역산당할 위험이 있습니다.
    - 반면 하드웨어 난수(**TRNG / Cloud HSM**)는 물리적 잡음을 측정하므로
      비결정론적(Non-deterministic)이며 완벽히 예측 불가능합니다.
  - **IaC(Terraform) 거버넌스**:
    - 인프라 코드는 실행할 때마다 항상 동일한 인프라 상태를 재현할 수 있는 결정론적
      멱등성(Idempotency)을 보장해야 합니다.

### E

#### Egress (이그레스 / 송신 트래픽) ⭐

- **정의**: 네트워크, 시스템(서버, 컨테이너), 또는 VPC 내부에서 외부나 타 네트워크 영역으로 나가는
  **'아웃바운드(Outbound) 송신 트래픽'**을 뜻합니다.
- **보안 및 아키텍처 중요성**:
  - 인바운드(Ingress) 침투 방어만큼이나 기밀 데이터 유출(Exfiltration) 방지와 컴플라이언스 감사를
    위해 엄격한 송신 트래픽 통제가 필수적입니다.
  - **Cloud Run / Serverless VPC Access 제어**:
    - `private-ranges-only`: RFC 1918 사설 IP 대역(Cloud SQL 등) 목적지만 VPC 커넥터로 전달하고,
      인터넷 트래픽은 기본 게이트웨이로 직행 (비용/대역폭 최적화).
    - `all-traffic`: 모든 송신 트래픽을 VPC 커넥터로 강제 유입하여 VPC 내 **Cloud NAT(고정 외부
      IP)**를 경유하도록 구성.

#### Exfiltration (데이터 유출 / 반출) ⭐

- **정의**: 컴퓨터나 조직의 네트워크 내부에서 인가되지 않은 방식으로 중요하고 민감한 데이터(기밀
  문서, 고객 개인정보, 지적 재산 등)를 몰래 빼내 외부로 전송/유출하는 사이버 범죄 행위(Data
  Exfiltration)를 뜻합니다.
- **클라우드 환경의 주요 공격 시나리오**:
  - 인가된 직원이 악의를 품고 내부 BigQuery 데이터를 개인 소유의 외부 프로젝트 버킷으로 복사.
  - 탈취된 서비스 계정 키를 이용해 Cloud Storage 객체를 외부 인터넷 서버로 전송.
  - DNS 터널링(DNS Tunneling)을 통한 소량 분할 데이터 외부 전송.
- **Google Cloud의 주요 방어 대책**:
  - **VPC Service Controls (VPC SC)**: BigQuery, Cloud Storage 등 관리형 API 주변에 강력한 보안
    경계(Service Perimeter)를 설정하여, 인증된 사용자라 할지라도 인가되지 않은 외부 프로젝트로
    데이터를 전송하는 행위를 원천 차단합니다.
  - **Sensitive Data Protection (Cloud DLP)**: 데이터 내 민감 정보(주민등록번호, 카드번호)를 사전
    마스킹 및 암호화하여 유출되더라도 식별 불가하게 조치.
  - **Event Threat Detection (ETD)**: 대량 데이터 다운로드 및 비정상적인 데이터 전송 행위를 실시간
    감사 로그 분석으로 탐지.

---

### F

#### FIPS 140-2 Level 3

- **정의**: 미국 국립표준기술연구소(NIST)의 하드웨어 보안 모듈 인증 표준.
- **핵심 특징**: 물리적 장비 분해, 전압/온도 공격 등 물리적 침투가 감지되면 칩 내부의 암호키
  데이터를 즉시 0으로 덮어써서 스스로 파괴(Zeroization)하는 고도의 물리 보안 등급입니다. (GCP의
  **Cloud HSM**이 이를 충족합니다.)

---

### I

#### IdP (Identity Provider, 신원 제공자) ⭐

- **정의**: 사용자의 신원 정보(계정 ID, 비밀번호, MFA, 부서/역할 속성)를 중앙에서 생성·보관하고,
  클라우드 서비스나 웹 애플리케이션의 로그인 요청 시 사용자가 본인임을 인증(Authentication)하여
  디지털 자격 증명(SAML Assertion, OIDC JWT 토큰 등)을 발급해 주는 **중앙 신원 인증 시스템**입니다.
- **대표적 솔루션**: Okta, Microsoft Entra ID (구 Azure AD), Ping Identity, Google Cloud Identity.
- **클라우드 연동 가치**: 모든 사원 계정을 GCP에 개별 생성하지 않고, 단일 IdP와 자격 증명
  제휴(Federation)하여 입사/퇴사 시 계정 수명주기를 중앙에서 일괄 통제합니다.

### J

#### Jailbreak Attempts (탈옥 시도)

- **AI/LLM 보안**: 대형 언어 모델의 안전 가드레일(Safety Alignment) 및 시스템 프롬프트 제약을
  우회(Bypass)하여 금지된 응답 생성을 유도하는 프롬프트 인젝션 공격. (방어: **Model Armor**)
- **전통적 모바일 보안**: OS 커널 취약점을 공격하여 샌드박스를 해제하고 최고 관리자(Root) 권한을
  강제 획득하려는 시도.

### L

#### Lateral Movement (측면 이동 / 횡적 이동) ⭐

- **정의**: 공격자가 네트워크 내부의 한 시스템이나 계정(최초 침투 지점)을 장악한 후, 내부망을
  수평으로 이동하며 **더 높은 권한(관리자 권한)이나 핵심 기밀 데이터(DB, IAM 키 등)를 찾아 침투
  범위를 넓혀가는 사이버 공격 단계(MITRE ATT&CK TA0008)**입니다.
- **직관적 비유**:
  - 도둑이 보안이 허술한 화장실 창문(외부 웹서버)으로 집 안에 발을 들인 뒤, 안방 금고(고객 DB)를
    털기 위해 집 안의 다른 방들을 하나씩 열고 돌아다니는 행위입니다.
- **클라우드 환경의 주요 횡적 이동 시나리오**:
  - **메타데이터 서버(IMDS) 토큰 탈취**: 웹 취약점으로 VM을 장악한 후 메타데이터 서버에서 서비스
    계정 액세스 토큰을 빼내 BigQuery, Cloud Storage 등 내부 자산으로 접근.
  - **과도한 기본 권한 악용**: 프로젝트 `Editor` 권한을 가진 기본 Compute Engine 서비스 계정을 타고
    프로젝트 전체를 장악.
  - **개발 환경에서 운영 환경으로 점프**: 느슨하게 관리되는 개발망(Dev)을 뚫고 내부 VPN이나 피어링을
    통해 운영망(Prod)으로 침투.
- **Google Cloud의 핵심 방어 대책**:
  - **최소 권한(Least Privilege) 및 서비스 계정 격리**: VM별로 전용 서비스 계정을 분리 생성하고 기본
    서비스 계정(`Editor`) 사용 금지.
  - **GKE Workload Identity**: 파드 단위로 IAM 역할을 쪼개어 특정 컨테이너가 침해되어도 노드 내 다른
    파드로의 권한 확산 방지.
  - **서브넷 격리 & 마이크로 세그멘테이션(Firewall Rules)**: 내부망이라도 모든 트래픽을 기본
    차단(`Default Deny`)하고 필수 포트만 허용.
  - **VPC Service Controls (VPC SC)**: 탈취된 서비스 계정 토큰이라도 인가되지 않은 외부나 타
    프로젝트로 데이터를 빼내지 못하도록 API 레벨 격리.
  - **Event Threat Detection (ETD)**: 비정상적인 내부 서비스 계정 사용 및 토큰 남용을 실시간 탐지.

#### Log Sink (로그 싱크) ⭐

- **정의**: Cloud Logging에서 수집된 대량의 로그 항목(Log Entry) 중, 사전 정의된 필터(Filter) 조건에
  일치하는 로그를 특정 외부 목적지(Destination)로 실시간 분기/전송하는 **전송
  파이프라인(배관)**입니다.
- **지원 목적지 규격**:
  - **BigQuery 데이터세트**: 대용량 보안/감사 로그의 고성능 SQL 분석
  - **Cloud Storage 버킷**: 장기 규정 준수(Compliance) 콜드 아카이빙
  - **Pub/Sub 주제**: SIEM(Splunk, Datadog 등) 실시간 연동
  - **Log Bucket**: Cloud Logging 내부 저장소 (Linked Dataset은 가상 뷰이므로 싱크 목적지 불가)
- **핵심 보안 제약사항**:
  - 싱크 생성 시 Cloud Logging 전용 서비스 계정인 **`writerIdentity`**가 자동 발급됩니다.
  - 목적지(예: BigQuery)에 이 `writerIdentity`를 대상으로 적절한 쓰기
    권한(`roles/bigquery.dataEditor`)을 명시적으로 부여하지 않으면, **Permission Denied로 인해
    로그가 유실**됩니다.

### N

#### Nearline Storage (니어라인 스토리지) ⭐

- **정의**: 데이터에 자주 접근하지는 않지만(월 1회 미만), 필요할 때는 밀리초(ms) 단위로 즉시 읽어야
  하는 데이터를 저장하기 위해 저렴한 저장 비용과 최소 보관 기간(30일)을 제공하는 **Cloud Storage의
  웜(Warm) 스토리지 클래스**입니다.
- **핵심 엔지니어링 및 비용 규칙**:
  - **최소 보관 기간 (30일)**: 객체 생성 또는 전환 후 30일 이전에 삭제하거나 Coldline/Archive로
    다운그레이드할 경우, 남은 일수만큼 **조기 삭제 수수료(Early Deletion Fee)**가 일할 계산되어
    청구됩니다.
  - **즉각적인 접근성 (Millisecond Latency)**: 별도의 복원(Retrieval) 대기 시간 없이 Standard
    클래스와 동일한 속도로 즉시 데이터를 조회할 수 있습니다.
  - **데이터 검색 비용(Retrieval Fee)**: 저장 단가는 Standard보다 저렴하지만, 데이터를
    다운로드하거나 읽을 때 GB당 검색 비용이 발생합니다.
- **대표적 활용 사례**:
  - 월 1회 실행되는 정기 데이터 백업
  - 생성 후 30일 이상 지난 규정 준수 감사 로그(Audit Logs)
  - 자주 열람하지 않는 멀티미디어 및 증빙 서류 아카이브

#### Nonconcurrent (비동시성 / 비동시 실행) ⭐

- **정의**: 여러 작업(Job, Task, 파이프라인)을 동일한 시점에 병렬(Concurrently)로 실행하지 않고,
  **순차적(Sequentially, 하나씩 직렬 처리)** 또는 작업 큐를 통해 한 번에 하나의 프로세스만
  실행되도록 통제하는 처리 방식입니다.
- **주요 엔지니어링 가치**:
  - **경쟁 상태(Race Condition) 및 데이터 오염 방지**: 동일한 공유 자원(DB 레코드, 공유 파일 시스템,
    인프라 상태 파일 등)에 동시 다발적인 쓰기 작업이 일어날 때 발생하는 교착 상태(Deadlock)나 정합성
    훼손을 방지합니다.
  - **시스템 부하 및 Rate Limit 보호**: 외부 서드파티 API 호출 한도(Quota 초과)나 순간적인
    CPU/메모리 스파이크를 방어하기 위해 작업을 직렬화(Serialization)합니다.
  - **CI/CD 및 IaC(Terraform) 거버넌스**: 동일한 대상 인프라나 `terraform.tfstate` 파일에 여러
    빌드가 동시에 반영되지 않도록 파이프라인 동시 실행 제한(Concurrency Limit = 1)을 걸어 단일
    배포의 원자성을 보장합니다.
- **주의 (유사 스펠링 혼동 방지)**:
  - 시스템 아키텍처의 비동시 처리는 **Nonconcurrent**이며, Cloud Storage 객체 버전 관리의 이전 세대
    구버전은 **Noncurrent**로 서로 다른 영역의 용어입니다.

#### Noncurrent Object (비활성 객체 / 구버전 객체) ⭐

- **정의**: Google Cloud Storage 버킷에 **객체 버전 관리(Object Versioning)**가 켜져 있을 때, 새
  파일이 덮어쓰여지거나(Overwrite) 현재 파일이 삭제되었을 때 히스토리로 남겨지는 **'이전 세대의
  구버전 객체'**를 뜻합니다.
- **수명 주기 관리(Lifecycle Management) 핵심**:
  - 버전 관리 버킷에서 일반 `Delete`를 수행하면 최신 버전(Live)이 Noncurrent로 전환될 뿐 버킷에서
    완전히 영구 삭제되지 않고 스토리지를 계속 차지합니다.
  - 따라서 규정 준수 만료 시 모든 과거 버전까지 영구 파기하려면 생명주기 규칙에
    `daysSinceNoncurrentTime` 또는 `isLive: false` 조건을 걸어 Noncurrent 객체를 명시적으로
    타겟팅해야 합니다.

### O

#### OIDC (OpenID Connect) ⭐

- **정의**: OAuth 2.0 인가(Authorization) 프레임워크 기반 위에 사용자 신원 증명 레이어를 추가한
  **글로벌 표준 인증(Authentication) 프로토콜**입니다.
- **핵심 메커니즘 (ID Token)**: 암호학적으로 서명된 **JSON 웹 토큰(JWT)** 형태의 ID Token을
  발급하여, 사용자의 신원(sub), 이메일, 그룹, 부서 정보 등을 안전하게 전달합니다.
- **GCP 자격 증명 제휴에서의 역할**: Workforce Identity Federation 및 Workload Identity Federation
  연동 시, 외부 IdP(Okta, GitHub, Azure 등)가 발급한 OIDC 토큰을 Google STS(Security Token
  Service)가 검증하여 구글 임시 액세스 토큰으로 교환해 주는 핵심 매개체입니다.

### P

#### Packet Mirroring (패킷 미러링) ⭐

- **정의**: Compute Engine 가상머신(VM)이나 특정 서브넷을 통과하는 인바운드 및 아웃바운드 원본
  네트워크 트래픽을 가상 스위치 레벨에서 **실시간 복제(Mirror)하여 보안 분석 수집기나 Cloud IDS
  엔드포인트로 전송**해 주는 완전 관리형 네트워크 기능입니다.
- **핵심 엔지니어링 제약사항**:
  - **동일 리전(Same Region) 필수**: 대역폭 비용 및 지연 시간 방지를 위해 모니터링 대상 리소스와
    수집기는 **반드시 동일 리전**이어야 합니다. (크로스 리전 패킷 미러링 불가)
- **보안 및 운영 강점**:
  - VM 게스트 OS에 에이전트를 설치하지 않고도(Agentless), 동일 서브넷 내부 VM 간 통신(L2)을 포함한
    모든 트래픽을 원본 영향 없이(비침해적) 100% 감시할 수 있습니다.

#### Private Google Access (PGA, 비공개 Google 액세스)

- **정의**: 공용 외부 IP가 없는 사설 VM이 Google 내부 백본망을 통해 Cloud Storage, BigQuery 등
  Google API 서비스에 비공개로 접근할 수 있게 해주는 **서브넷 레벨** 기능.

#### Private Service Connect (PSC)

- **정의**: 다른 VPC의 서비스, Google API, 서드파티 SaaS를 내 서브넷 내부의 사설 IP(엔드포인트)로
  끌고 와 연결하는 차세대 제로 트러스트 연결 기술 (IP 대역 중복 문제 없음).

#### PRNG (Pseudo-Random Number Generator, 소프트웨어 난수 / 의사 난수) ⭐

- **정의**: 컴퓨터 프로그램 코드와 수학 공식으로 계산해 낸 **'가짜 난수(의사 난수)'**입니다.
- **보안 위험성**:
  - 시작 값(Seed)이나 시간 값을 알면 공격자가 **다음에 나올 난수를 완벽히 역산/예측**할 수 있습니다.
  - 만약 인증 세션 토큰을 소프트웨어 난수로 만들면, 해커가 토큰 패턴을 추측하여 다른 사용자의 세션을
    탈취(Session Hijacking)할 위험이 생깁니다.
- **GCP 매핑**: Cloud KMS의 소프트웨어 보호 수준(`protectionLevel: SOFTWARE`, FIPS 140-2 Level 1).

#### Provisioning (프로비저닝) ⭐

- **정의**: 사용자가 즉시 업무나 서비스를 수행할 수 있도록, **서버(컴퓨팅), 스토리지, 네트워크 등 IT
  인프라 자원이나 사용자 계정 및 접근 권한을 사전에 준비하고 할당·배포하는 일련의 과정**을 뜻합니다.
- **주요 프로비저닝 유형**:
  - **인프라 프로비저닝 (Infra Provisioning)**: Terraform(IaC)이나 gcloud CLI를 통해 VM, 서브넷,
    방화벽, 데이터베이스 등을 코드로 자동 생성하고 배포하는 작업.
  - **사용자 / 계정 프로비저닝 (User Provisioning)**: 신규 입사자나 서비스 계정에 Cloud
    Identity/Workspace를 통해 계정을 발급하고 직무에 맞는 IAM 역할 그룹에 자동으로 할당하는 절차.
  - **동적 프로비저닝 (Dynamic / Auto-provisioning)**: 트래픽 급증 시 오토스케일링 규칙에 따라
    컨테이너(Cloud Run, GKE)나 프록시 VM(Serverless VPC Access)을 실시간으로 자동 확장 및 준비하는
    메커니즘.
- **보안 및 거버넌스 관점**:
  - **IaC 기반 안전한 프로비저닝**: 수동 콘솔 조작으로 인한 설정 오류(휴먼 에러)를 방지하고, 보안
    가드레일을 파이프라인에서 사전 검증(CI/CD)합니다.
  - **디프로비저닝(Deprovisioning)의 중요성**: 퇴사자 계정이나 프로젝트 종료 후 방치된 유휴 리소스를
    적시에 회수(Deprovisioning)하지 않으면 자격증명 유출 및 불필요한 비용 발생의 원인이 됩니다.

### R

#### Redact / Redacted (마스킹 / 비식별화 가림 처리) ⭐

- **정의**: 문서, 보고서, 이미지 등에서 기밀, 개인정보(PII), 민감한 내용 등을 보안이나 법적 이유로
  검열하여 **삭제하거나 검은색 박스 등으로 가려(블라인드/마스킹 처리) 놓은 상태**를 뜻합니다.
- **어원 및 배경**: 원래 동사 형태인 'redact'는 '(원고 등을) 수정하다, 편집하다'라는 뜻이지만,
  현대에는 주로 공공 문서나 법적 서류에서 민감한 정보를 지우는 행위를 가리킵니다.
- **GCP 보안에서의 대표적 구현체**:
  - **Sensitive Data Protection (Cloud DLP)의 `image.redact` API**:
    - 스캔된 이미지 원본을 전송하면 별도의 Vision OCR 파이프라인 없이도, DLP 내부 자체 OCR로
      텍스트를 읽고 `PERSON_NAME`, `EMAIL_ADDRESS`, `PHONE_NUMBER` 등의 민감 영역을 검은색 박스로
      덧칠(Redact)한 이미지를 단 1번의 호출(One Call)로 반환합니다.

#### Responsibility (역할 책임 / 실행 책임) ⭐

- **정의**: 일을 시작하기 전이나 진행 중에 맡은 바 과업(Task)을 완수하기 위해 최선을 다하려는
  **자발적이고 사전적인 실행 책임**입니다.
- **핵심 속성 (RACI 매트릭스의 'R')**:
  - **위임 가능 (Delegable)**: 실무자 간에 업무를 분담하거나 하위 담당자에게 위임하여 함께 수행할 수
    있습니다.
  - **복수 주체 가능**: 여러 명의 엔지니어가 하나의 보안 구현 과업에 대해 공동 실행 책임을 질 수
    있습니다.
- **클라우드 보안 및 거버넌스 맥락**:
  - 클라우드 엔지니어와 개발팀은 방화벽 규칙 배포, 암호키 생성, 테라폼 코드 작성 등 구체적인 보안
    대책을 올바르게 구현할 **실행 책임(Responsibility)**을 가집니다.
  - **Accountability와의 결정적 차이 요약**:
    - `Responsibility (역할 책임)`: "실제로 이 일을 실행하고 구현하는 사람 (Doer)" ➔ 위임 가능, 복수
      지정 가능
    - `Accountability (결과 책임)`: "일의 성패와 규정 준수에 대해 최종 설명하는 사람 (Owner)" ➔
      **위임 불가, 단일 소유자 원칙**

### S

#### Serverless VPC Access Connector (서버리스 VPC 액세스 커넥터) ⭐

- **정의**: Cloud Run, Cloud Functions 등 Google 관리형 서버리스 환경에서 고객사의 VPC 내부
  사설망(Cloud SQL Private IP 등)으로 안전하게 진입할 수 있도록 중계해 주는 **전용 인프라
  브릿지(커넥터)**입니다.
- **내부 아키텍처 실체**:
  - 단순 소프트웨어 파이프가 아니라, 서브넷 내부에서 **최소 2대 ~ 최대 10대까지 자동
    스케일링(Auto-scaling)되는 초소형 프록시 VM 인스턴스 클러스터**입니다.
- **핵심 3대 설계 원칙**:
  1. **리전 일치**: 서버리스 서비스와 커넥터는 **반드시 동일 리전**이어야 합니다.
  2. **서브넷 크기**: 정확히 **`/28` (총 16개 IP, 가용 12개)** 크기여야 합니다. (VM 10대 + 교체
     여유분 2대 수용)
  3. **미사용 전용 대역(Dedicated Unused Range)**: 일반 GCE나 GKE 리소스와 서브넷을 혼용할 경우
     스케일 아웃 시 **IP 충돌(IP Conflict)**로 커넥터 서비스 전체가 다운되므로 단독 전용 서브넷을
     사용해야 합니다.

#### Subnet (서브넷) ⭐

- **정의**: 글로벌 가상 사설망(VPC) 내부의 IP 주소 공간을 관리, 성능, 보안 목적에 맞게 특정
  리전(Region) 단위로 분할하여 VM 인스턴스 등에 사설 IP를 할당하는 **리전 종속 하위
  네트워크**입니다.
- **핵심 엔지니어링 속성**:
  - **리전 종속성 (Regional)**: VPC는 전 세계에 걸치지만, 서브넷은 반드시 특정 단일 리전(예:
    `asia-northeast3`)에 속합니다.
  - **GCP 4대 예약 IP**: 서브넷 대역 중 `.0`(네트워크), `.1`(게이트웨이), `.2`(DNS/메타데이터),
    마지막 IP(브로드캐스트) 총 4개는 인프라가 예약하므로 사용자가 VM에 할당할 수 없습니다.
  - **보안 격리**: 서브넷 경계와 방화벽 규칙을 결합하여 외부 공개 영역(DMZ)과 내부 기밀 DB 영역을
    격리하고 횡적 이동(Lateral Movement)을 방어합니다.

### T

#### TRNG (True-Random Number Generator, 하드웨어 난수 / 순수 난수) ⭐

- **정의**: 수학 공식이 아닌, **전용 하드웨어 칩 내부의 미세한 물리적 현상(열잡음, 전파 노이즈 등)을
  측정**하여 생성하는 **'진짜 난수(물리적 난수)'**입니다.
- **보안 강점**:
  - 수학 공식이 아니므로 **지구상 어떤 슈퍼컴퓨터로도 다음 값을 예측할 수 없습니다.**
  - 세션 토큰 시드, 암호화 키 생성, 금융 결제망(PCI DSS) 등 최고 수준의 예측 불가능성이 필요할 때
    필수적입니다.
- **GCP 매핑**:
  - **Cloud HSM** (`protectionLevel: HSM`, FIPS 140-2 Level 3 인증 물리 칩).
  - Cloud KMS의 **`generateRandomBytes` API**를 호출하여 물리 HSM 칩에서 직접 순수 난수(1회 호출당
    최대 1024바이트)를 추출할 수 있습니다.

### V

#### VPC (Virtual Private Cloud, 가상 사설 클라우드) ⭐

- **정의**: Google Cloud 글로벌 인프라 위에 생성되는 **고객사 전용의 독립적이고 격리된 소프트웨어
  정의 사설 네트워크(SDN)**입니다.
- **핵심 아키텍처 특성**:
  - **글로벌 스코프 (Global Scope)**: 타 클라우드(AWS 등)와 달리 GCP의 VPC는 전 세계 모든 리전에
    걸쳐 있는 글로벌 리소스입니다. 별도의 리전 간 VPN이나 피어링 없이도 서로 다른 리전의 서브넷 간
    통신이 Google 내부 백본망을 통해 암호화되어 직접 이루어집니다.
  - **기본 게이트웨이 및 라우팅**: 모든 서브넷 간의 트래픽을 자동으로 라우팅하는 가상
    라우터(Andromeda)를 기본 내장합니다.
  - **방화벽 규칙(Firewall Rules)**: VPC 단위로 상태 저장(Stateful) 분산 방화벽 규칙을 적용하여 모든
    인바운드/아웃바운드 트래픽을 제어합니다.

### W

#### Workforce Identity Federation (인력 자격 증명 제휴) ⭐

- **정의**: 사내 외부 IdP(Okta, Azure AD/Entra ID 등 - OIDC/SAML 지원)를 사용하는
  **직원(사람/Workforce)**들이, Google Cloud Identity에 별도 계정을 생성하거나 동기화하지
  않고도(`no Google accounts`) **기존 회사 계정으로 GCP 콘솔(Web UI)과 gcloud CLI에 직접 로그인**할
  수 있도록 지원하는 차세대 IAM 연동 기술입니다.
- **핵심 차별점**:
  - **콘솔(Web UI) 로그인 지원**: 전용 IdP 로그인 포털 URL을 통해 브라우저 웹 콘솔 접속을 완벽히
    지원합니다.
  - **이중 계정 관리 배제**: 구글 쪽에 두 번째 계정 세트가 생기지 않으므로 입사/퇴사 시 사내
    IdP에서만 계정을 비활성화하면 GCP 접근 권한이 즉시 차단됩니다.

#### Workload Identity Federation (워크로드 자격 증명 제휴) ⭐

- **정의**: AWS, Azure, GitHub Actions, 온프레미스 서버 등 외부 환경에서 실행되는 **소프트웨어
  애플리케이션 및 CI/CD 러너(기계/Workload)**가, 유출 위험이 높은 영구 서비스 계정 키(JSON 키 파일)
  없이도 GCP 리소스에 안전하게 접근할 수 있게 해주는 무키(Keyless) 인증 기술입니다.
- **Workforce와의 결정적 차이**:
  - 대상이 '기계(Workload)'이므로 **오직 API/CLI 통신만 지원**하며, 사람이 브라우저로 웹 콘솔 화면에
    로그인하는 기능은 지원하지 않습니다.

### Z

#### Zero Trust (BeyondCorp)

- **정의**: *"절대 신뢰하지 말고, 언제나 검증하라(Never Trust, Always Verify)"*를 원칙으로, 사내
  네트워크 내부라도 신뢰하지 않고 모든 접근 요청에 대해 신원(ID)과 기기 보안 상태(Context)를
  지속적으로 검증하는 보안 패러다임. (구현체: **IAP**, **Context-Aware Access**)
